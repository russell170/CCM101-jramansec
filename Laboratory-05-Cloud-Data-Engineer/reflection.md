# Reflection

In this activity, I learned more about cloud storage and how Object Storage can be used for applications that need to store a large amount of data. I learned that Object Storage is better for storing millions of photos because it is designed for unstructured data such as images, videos, backups, and other files. It can also handle a large number of objects without storing everything directly on the web server. I also learned how Docker made the deployment of MinIO easier because I only needed to use a Docker command to create and run the MinIO container. Instead of manually installing and configuring MinIO, Docker allowed me to quickly set up the service and configure the required ports and environment variables. I also learned that a bucket is a container used to organize and store objects in an object storage system. In this activity, I created a bucket named `client-photos` and uploaded a test file to make sure that the MinIO storage system was working properly. I learned that enterprises can help prevent data loss when a physical server crashes by using multiple copies of data and storage systems that provide redundancy. This means that data can still be available even when one physical server experiences a problem. The activity also helped me improve my understanding of Linux command-line tools. At first, using commands in the terminal can be confusing, but after running Docker commands and checking the status of the MinIO container, I became more comfortable using the command line. I learned how commands can be used to deploy, manage, and verify services without relying only on a graphical interface. Overall, this activity improved my understanding of Object Storage, Docker, MinIO, buckets, and Linux commands. It also showed me how these technologies can work together to provide a practical solution for storing and managing large amounts of data in a cloud environment.
